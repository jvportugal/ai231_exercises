# Fitted waveform replay results

The eight-stage research policy in `eighteen_extended_robust_development.json`
selects between existing model predictions and time- or frequency-transformed
feature predictions. It adds no model parameters, but can run the model
multiple times. No Raspberry Pi latency, memory, or device test has been done.
It has not been deployed.

Both historical TEST and HOLDOUT labels were used repeatedly to construct and
select this policy, including its individual thresholds. These are fitted
development results, not independent test or generalization estimates. A
FIT-only selection experiment improved FIT but lost real and synthetic commands
on the other TEST portion and on historical HOLDOUT. That is evidence of
substantial overfitting risk. The reused original models also have historical
noise provenance that is not certified against the current data restrictions.

The actual waveform/frontend/ONNX replay recorded the following clean results:

| Measure | Research baseline | Fitted policy |
| --- | ---: | ---: |
| TEST real command | 609/777 (78.38%) | 663/777 (85.33%) |
| TEST synthetic command | 3542/3590 | 3558/3590 |
| TEST combined command | 4151/4367 (95.05%) | 4221/4367 (96.66%) |
| TEST native OOS rejection | 64/76 (84.21%) | 70/76 (92.11%) |
| TEST tuning OOS rejection | 355/400 | 378/400 |
| HOLDOUT real command | 77/86 (89.53%) | 78/86 (90.70%) |
| HOLDOUT synthetic command | 99/100 | 99/100 |
| HOLDOUT combined command | 176/186 (94.62%) | 177/186 (95.16%) |
| HOLDOUT native OOS rejection | 13/16 (81.25%) | 16/16 (100%) |
| HOLDOUT filtered negative rejection | 113/120 | 117/120 |

The 16 holdout native OOS recordings are a small sample. Exact machine-readable
outputs are `eighteen_extended_robust_actual_test.json` and
`eighteen_extended_robust_actual_holdout.json`. The replay implementation is
`../verify_eighteen_extended_runtime_20261102.py`; it is research code and
uses PyTorch for feature transformation, not a deployable Pi implementation.
Future evaluation requires new, permitted speaker recordings that were not
used for model or policy selection.

Additional procedural stress tests on the same holdout speech found material
regressions. With simulated room effects, real-command accuracy fell from
66/86 to 61/86 and native OOS rejection from 13/16 to 10/16. At the tested
6 dB procedural-noise setting, these changed from 39/86 to 34/86 and 11/16 to
7/16; at 12 dB, they changed from 65/86 to 60/86 and 11/16 to 9/16. These
views reuse the same recordings and do not constitute new speakers. The fitted
clean policy is not a suitable deployment candidate based on these results.

A 0.5-threshold acoustic-condition detector was subsequently trained on
filtered TRAIN recordings and procedural room/noise augmentations, with a
speaker-disjoint TRAIN validation split. It gates the fitted policy, falling
back to the research baseline when the detector identifies distorted audio.
The detector-gated full clean waveform replay retains the TEST counts above;
clean HOLDOUT remains 78/86 real and 16/16 native OOS, with filtered negatives
at 116/120. On the three stress draws above, detector-gated decisions matched
the baseline, avoiding those regressions but not improving noisy OOS rejection.
On additional draws, native OOS remained unchanged, while real commands fell
by one on the new room draw (65 to 64/86) and one at SNR30 (79 to 78/86).
All stress views reuse historical HOLDOUT recordings. The detector is itself
experimental; additional held-out speakers, noise conditions, deployment
implementation and Raspberry Pi performance remain unverified. Outputs are
`train_detector_gated_actual_{test,holdout}.json` and
`train_detector_gated_{stress,newseed}_holdout_*.json`.

An adaptive noise-reduction and conditional room-fallback research variant
also retained the clean TEST result of 663/777 real commands and 70/76 OOS,
and clean HOLDOUT of 78/86 and 16/16. Its SNR6 and SNR12 holdout draws
improved command accuracy, while some room views reverted to the baseline.
A related additive-noise verifier increased native OOS rejection on the
calibration draws. On a new noise draw applied to the historical TEST speech,
it improved SNR6 real commands from 332/777 to 375/777 and native OOS from
58/76 to 62/76; at SNR12 it improved real commands from 469/777 to 519/777
and OOS from 58/76 to 64/76. These noisy decisions were produced before a
subsequent narrow room-fallback correction, and the same speech was previously
used for development. At SNR6, even the improved real-command accuracy is
only 48.26%; room audio can still fall below the OOS goal. A separate room
verifier fitted on holdout room views improved OOS but reduced real TEST room
commands from 524/777 to 447/777, so it was rejected. None of these results
is independent generalization evidence or a Raspberry Pi measurement.
## Additional noise experiments

Stronger spectral subtraction and a noise-level guard improved noisy speech,
but did not meet the real-command target in the tested low-SNR conditions.
With an OOS verifier whose thresholds were fitted to reused test and holdout
noise views, a new noise draw applied to the same holdout speech produced:

| Procedural condition | Real commands before → after | Native OOS before → after |
| --- | --- | --- |
| 6 dB, seed 230400 | 33/86 → 61/86 | 11/16 → 15/16 |
| 12 dB, seed 230400 | 61/86 → 69/86 | 14/16 → 16/16 |

The noise draw is new; the recordings and model-selection process are not
independent. Clean holdout replay with this rule remained 78/86 real commands,
99/100 synthetic commands, and 16/16 native OOS. Clean test replay for the
same rule produced 663/777 real commands, 3558/3590 synthetic commands,
70/76 native OOS and 377/400 tune OOS. The rule permitted up to two lost real commands out
of 86 in each fitted holdout noise view, slightly more than two percentage
points. Other room conditions and noise draws can still fail. Existing model
weights have uncertified historical noise provenance. These experiments have
not been deployed or measured on a physical Pi.

The same frozen rule did not consistently improve OOS on test speech: on
the new 12 dB noise draw, real commands increased from 473/777 to 531/777,
while native OOS rejection fell from 59/76 to 57/76. The new 6 dB draw gave
328/777 to 437/777 real commands and 56/76 to 64/76 native OOS. A separate
TRAIN-only noise-specific verifier was also trained, but its initial
thresholds caused substantial valid-command losses and are not promoted.

A later two-head rule fitted additional previously inspected noise views. Its
clean waveform replay retained the test and holdout real, synthetic, and
native-OOS counts listed above. On subsequently drawn procedural noise seeds,
it produced test real-command/OOS counts 415/777 and 66/76 at 6 dB, 525/777
and 63/76 at 12 dB (seed 240500); 426/777 and 67/76 at 6 dB, 509/777 and
65/76 at 12 dB (seed 250600). On the same draws the holdout results were
60/86 and 15/16, 72/86 and 16/16, 58/86 and 16/16, and 69/86 and 14/16,
respectively. This is limited evidence on new white/colored noise with reused
speech; low-SNR real-command accuracy remains below the stated goal.

## Later selective smoothing candidate

A 1,537-parameter feature correction trained on filtered permitted TRAIN
speech and procedural noise was combined with existing rejection rules and a
class-selected, smoothed spectral filter. Its rules were selected using the
same TEST and HOLDOUT recordings, so the results below are development results,
even where the procedural noise seed was new. The historical recognizer's
training-noise provenance remains uncertified. The estimated combined model
has 3,191,567 parameters, below the 3,192,807 budget; inference cost and Pi
latency have not been measured.

Correction: the restorer's original TRAIN validation split used a combination
of source and speaker ID, which does not ensure speaker separation across
sources. The full filtered TRAIN table has 17 speaker IDs on both sides of
that grouping. Its validation figures must not be called speaker-disjoint.
The same issue also affects the acoustic detectors described above: their
TRAIN validation was grouped by source and speaker, not speaker ID alone.
A new restorer run groups by speaker ID instead.

Clean HOLDOUT waveform replay achieved 78/86 real commands, 99/100 synthetic
commands and 16/16 native OOS. Full waveform replay of this combined policy
achieved 663/777 real commands, 3558/3590 synthetic commands, 70/76 native OOS
and 377/400 tune OOS on clean TEST. Two raw baseline predictions differed
from a prior cache, but the reported waveform counts are from the replay.

On new procedural-noise seed 420300, the combined policy achieved 56/86 real
commands and 14/16 native OOS on HOLDOUT at 6 dB; TEST achieved 428/777 and
70/76. At 12 dB it achieved 64/86 and 15/16 on HOLDOUT, and 510/777 and 67/76
on TEST. Compared with the immediately preceding policy, the 6 dB TEST result
gained one OOS rejection and lost one real command; the 6 dB HOLDOUT result
lost one real command with no OOS gain. Other draws show different tradeoffs.
Six and twelve dB are added-noise conditions, not physical microphone distance
or measured total SNR. The low-SNR real-command targets are not met, and 16
native HOLDOUT OOS clips are too few to establish robust rejection. Nothing
has been deployed.

## Retrained correction model

A second 1,537-parameter correction model was trained on 3,400 filtered TRAIN
recordings with procedural noise, using speaker-ID grouping for TRAIN
validation. Its selected checkpoint retains the clean waveform counts above
on both TEST and HOLDOUT. The long recognizer is still the historical model
with uncertified noise provenance; this does not certify the complete stack.

At 6 dB, compared with the preceding combined policy, the new checkpoint's
TEST real/native-OOS counts changed from 434/777 and 67/76 to 437/777 and
68/76 on seed 380900; 416/777 and 70/76 to 424/777 and 70/76 on seed 430500;
441/777 and 65/76 to the same counts on seed 450700; and 436/777 and 67/76
to 437/777 and 67/76 on new noise seed 460800. HOLDOUT real/native-OOS counts
were unchanged on those draws except seed 450700, where real accuracy rose
from 57/86 to 59/86 with native OOS unchanged at 16/16. At 12 dB seed
430500, real/native counts were unchanged for both sets. These are still
reused development recordings and tiny absolute gains: 6 dB real-command
accuracy remains far below the goal. The model has not been deployed.

## Additional intent correction

A 1,216-parameter rank-four intent correction trained on filtered permitted
TRAIN speech was added experimentally to the preceding model. The estimated
stack is 3,192,783 parameters, 24 below the cap. Research waveform replays
retained the clean TEST and HOLDOUT counts reported above. No physical Pi
timing or memory measurement was made.

On 6 dB noise seed 470900, compared with the preceding model, TEST improved
from 430/777 to 432/777 real commands and from 66/76 to 67/76 native OOS;
HOLDOUT improved from 57/86 to 58/86 real commands, kept native OOS at 14/16,
and lost one tune OOS rejection (115/120 to 114/120). On another noise draw,
480000, TEST improved from 433/777 to 435/777 with native OOS unchanged at
66/76; HOLDOUT real and native OOS remained 69/86 and 13/16. On seed 490100,
HOLDOUT real accuracy fell from 61/86 to 59/86 while native OOS stayed 15/16;
TEST real and native OOS remained 429/777 and 69/76. At 12 dB seed 430500,
TEST and HOLDOUT real/native counts were unchanged. The recordings and
selection process remain development data, the holdout OOS sample is small,
and the historical base weights have uncertified noise provenance. Nothing
was deployed.

## Strict rejected-command guard

A separate 120-stump guard was trained on permitted TRAIN speech with
procedural noise and selected using speaker-grouped TRAIN validation. It
adds an estimated 483 scalar values to the earlier V2 stack. The underlying
waveform policy was already fitted on TEST and HOLDOUT; the guard's validation
was reused for threshold selection. Its complete clean waveform replay matched
the TEST and HOLDOUT counts above. The checked 12 dB draw also matched the V2
real-command and native-OOS counts.

On new 6 dB noise seeds 560800, 570900, 580000 and 590100, native OOS counts
on TEST and HOLDOUT were unchanged. TEST gained 1, 2, 1 and 2 real commands,
respectively, with no real-command gain on HOLDOUT. The guard also issued one
wrong command on the first draw and two on the fourth; the other two had no
new wrong commands. On earlier checked draws it gained one HOLDOUT command on
two views, but issued one wrong command on one of those. These are small,
development-set effects, not evidence of reliable behavior with new speakers;
6 dB real accuracy remains well below the stated goal. Pi latency, memory,
and complete historical noise provenance have not been verified. No model
or rule has been deployed.
